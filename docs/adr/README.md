# Architecture Decision Records

ADRs record design choices that should remain understandable after the
conversation that produced them is gone.

Use an ADR when:

- a decision could reasonably have gone another way;
- a future contributor might be tempted to undo it accidentally;
- the decision affects architecture, trace semantics, or project direction.

Keep ADRs short. They are not essays.

## Status Values

- Proposed: plausible, not yet relied on by implementation.
- Accepted: current working decision.
- Superseded: no longer current; link to the replacement.
