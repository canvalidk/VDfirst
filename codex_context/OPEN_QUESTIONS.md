# Open Questions

These are Code-branch questions that need Theory or Newton guidance before
they should be treated as settled.

## Trace Control Flow

- What exact event should cause a completed child demand to return to its
  parent?
- Should return be automatic, manual, or configurable in the simulator?
- When a child returns, should the simulator immediately continue with the
  next open position, or only update state and wait for the next command?

## Human Inputs

- What is the stable taxonomy of human inputs?
- Are recognition, modelling, empirical, and closure-forced inputs enough for
  the first proof of concept?
- What fields must every audit record contain?
- Should user `inject` be replaced by typed human-input commands, or should it
  remain a lower-level escape hatch?

## Newton Entries

- Which Newton entries should be treated as type signatures, computation
  rules, walls, chimneys, or laws by the simulator?
- How should the simulator choose between multiple entries for the same
  headword when one is a wall and another is a computation rule?
- What is the first representative Newton problem the simulator should solve
  end to end?

## Product Boundaries

- Which behaviours belong in the simulator versus the later LLM-facing
  Newton abacus?
- Which trace reports should be generated by Code versus written manually in
  Theory/Newton documents?
